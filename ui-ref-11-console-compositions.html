UI Reference · File 11

Console Compositions

Five complete screens built from the earlier files: an incident console, a pipeline DAG with log tail, a fleet table with date-range and bulk actions, a settings page with a permission matrix, and a status / SLO view. Every frame has a light / dark switch, a density switch, and a collapsible nav. Composition is where a console stops looking generic, so this file is about hierarchy and spacing more than any one control.

⚠ Reduce Motion is on in your OS. CSS animations and transitions are being suppressed.
00 — Composition rules

Eight rules every frame below follows

These are the decisions that make a screen read as considered. They are cheap, and they are the difference between a component pile and a product.

1 · Three surface levels, no more

--bg for the page, --surface for cards and tables, --bg-2 for chrome (nav, top bar, inspector). Nothing floats above that except overlays.

2 · Density is a token

Compact mode changes --pad, --row, --fs and control height. It never changes layout. Toggle it in any frame.

3 · One accent, spent carefully

The accent marks the current nav item, the selected row, the primary button and focus. It is not used for decoration, headings or icons.

4 · Status colour is data

Red, amber and green appear only where they mean something. A red KPI edge and a red row dot are both signals; a red header is noise.

5 · Tabular numerals everywhere

font-variant-numeric: tabular-nums on tables and KPIs. Mono for identifiers, timestamps and log lines only.

6 · Chrome is quiet

Nav and top bar sit on --bg-2 with hairline borders and no shadow. The content area is where contrast lives.

7 · Selection drives the inspector

Click a row or node and the right panel updates in place. No modals for read-only detail; modals are for destructive confirmation.

8 · Bulk actions float

Checking rows raises a floating action bar at the bottom centre. It carries the count, the actions and an escape hatch.

Porting notes. Each frame is one .app flex row: nav, main (top bar + scrolling content), optional inspector. Density is applied by setting data-density on the frame and letting tokens do the rest; try it in compact mode on the fleet table to see how much of a real console fits in 640px. The bulk bar is positioned against .app, not the table, so it stays put while the table scrolls. The DAG uses absolute-positioned HTML nodes over one SVG for edges; for a real graph, compute both from the same layout output (dagre or ELK) and keep the animation on the edge class, not the node. The date-range calendar renders from a tiny script below; the range logic is thirty lines and worth owning rather than importing.

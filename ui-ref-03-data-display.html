UI Reference · File 03

Data Display

The patterns an operations console actually lives on: sortable and expandable tables with sticky columns and selection, a severity-coloured log viewer with search, a collapsible JSON tree, line diffs, in-cell micro-charts, and event timelines.

⚠ Reduce Motion is on in your OS. CSS animations and transitions are being suppressed.
01 — Tables

Sort, select, expand, sticky column

Click a header to sort, a row to expand, the checkbox to select. Expansion uses the grid-template-rows: 0fr → 1fr trick — the only clean way to animate to an unknown height. The first column is position: sticky so identifiers stay visible while scrolling wide data.

02 — Log viewer

Severity colouring, filtering, search highlight

Severity drives a left border and a tinted row, not just coloured text — you want to spot errors while scrolling fast. Indented stack frames get dimmed so they read as detail rather than as separate events. Type in the search box to highlight matches.

03 — JSON & diff

Collapsible tree and line diff

Click any ▾ to collapse a node. Type colouring follows the usual convention: keys accent, strings green, numbers amber, booleans cyan, null faint. The diff view uses tinted rows plus generated +/- prefixes so it survives copy-paste.

06 — People, access & audit

Avatars and presence, permission matrix, audit log, uptime bars

Four things every console eventually needs and usually bolts on badly. Avatars are initials on a muted five-colour palette, never the accent. The permission matrix is a tri-state dot (allowed, own items only, denied) with locked cells. Audit entries lead with a verb, show before → after inline and expand to the raw diff. Uptime bars are 30 ticks coloured by the worst state of the day, with a tooltip on hover.

Porting notes. The expand animation needs the hidden row present in the DOM — display:none cannot be transitioned, which is why the 0fr/1fr grid trick exists. Sticky columns need an explicit background or content scrolls visibly underneath. For logs beyond a few thousand lines, virtualise: render only the visible window and pad with spacers, or the DOM node count will stall the browser.

01 — Keyboard

Focus rings, skip links, roving tabindex

Everything here is operable without a mouse. The roving-tabindex pattern is the one most internal tools miss: a long list should be a single tab stop with arrow-key movement inside, not one stop per row.

02 — Announcements

Live regions and non-colour status

Auto-refreshing dashboards are silently broken for screen readers — the number changes and nothing is announced. Watch the log fill as the value updates.

Light
ARIA live region — auto-refreshing numbers
485
Total runs · refreshes every 4s
Screen reader announcements appear here
A number that changes silently is invisible to a screen reader. Wrap it in aria-live="polite" and announce the meaning, not the digits: “Total runs updated to 487” rather than “487”. Use assertive only for genuine emergencies — it interrupts whatever is being read.
Status without relying on colour
✓Completed — icon + colour + text
!At risk — distinguishable in greyscale
×Failed — shape differs, not just hue
Colour-only dot — invisible to 8% of men
Red/green is the most common deficiency. Every status needs a second channel: an icon shape, a label, or a pattern.

03 — Contrast & forms

Ratios and accessible error messaging

Every token pair in a theme should be checked once and recorded, so component authors are not guessing. Form errors need four things wired together, not just a red border.

Light
Contrast pairs
Body text on surface 14.8:1 AAA
Secondary text 6.1:1 AA
Faint text — labels only, never body 3.2:1 fails AA
White on accent 4.9:1 AA
AA needs 4.5:1 for body text and 3:1 for large text or UI borders. Faint tokens are fine for uppercase labels at 700 weight but must never carry a sentence.
Accessible form errors
⚠Asset ID must be numeric, for example 5341
Four things together: a real <label>, aria-invalid, aria-describedby pointing at the message, and an icon so the error is not signalled by red alone. The message says how to fix it, not just that it is wrong.

04 — Dialogs & motion

Focus traps and vestibular safety

A dialog that does not trap focus lets keyboard users tab behind it into a page they cannot see. Reduced motion means replacing movement with a fade, not removing feedback entirely.

Reduced motion done properly
Left: large translation, which triggers vestibular discomfort. Right: opacity only, safe under reduced motion. The right answer is rarely “no animation” — it is substituting a fade for a movement, so state changes remain legible.

Porting notes. Four things carry most of the value and cost almost nothing: :focus-visible rings on every interactive element, real <label> elements on every input, aria-live on anything that updates itself, and a second non-colour channel on every status. Focus traps and roving tabindex take slightly more work but are the difference between a keyboard-usable tool and an unusable one. Test by unplugging the mouse for ten minutes — it finds more issues than any automated checker.

Theme Cookbook

One component set — KPI card, article card, badges, buttons, input, table, progress — rendered in five genuinely different aesthetics. Identical markup throughout; only the tokens change. Each block ships its full token list ready to copy into files 01–07.

⚠ Reduce Motion is on in your OS. CSS animations and transitions are being suppressed.
00 — How this works

Six axes make a theme, not just colour

Every demo below uses byte-identical markup. Only the token block changes. Swapping colours alone gives you a recolour; changing these six axes gives you a different product.

1 · Radius

--r, --r-sm, --r-pill. 0px reads technical, 12px reads product, 20px+ reads consumer.

2 · Motion

--ease, --dur. A theme with 0ms is a design decision, not a missing feature.

3 · Density

--pad, --gap, --fs. Components multiply the base pad rather than hardcoding spacing.

4 · Depth

--shadow, --bw. Shadow, hard offset, border-only, or flat — pick one and commit.

5 · Type

--font-ui, --font-display, --font-num. A separate display face does more work than any colour change.

6 · Emphasis

--upper, --tracking, --weight-bold. Uppercase labels and tracking set the formality register.

How to use this. Pick a theme, copy its token block, and paste it over the [data-t="dark"] block in any of files 01–07 — the components read only from tokens, so they re-skin without edits. To invent a new theme, copy the closest block and change the six axes one at a time; changing them all at once makes it impossible to tell which decision is not working. The components here are deliberately minimal so the theme is doing the visible work — if a pattern looks good in all five, it is structurally sound rather than carried by styling.
